Documentação da API

Backend da Academia London Fitness. Cobre conta, perfil, matrícula, locais, fichas (CRUD), plano da semana, execução série a série e histórico persistido ao finalizar o treino. Senha nunca é gravada em texto — apenas hash bcrypt.

JWT + refresh MASTER_KEY nas rotas privadas PostgreSQL CRUD de fichas Histórico ao finalizar Collection Postman em /docs Plano IA via Groq

Como autenticar

Envie o access token em todas as rotas privadas. O access token expira em 15 minutos. Use POST /api/auth/refresh para renovar. O admin mestre também pode usar a MASTER_KEY do .env no lugar do JWT — vale em qualquer rota privada e não expira. 

Authorization: Bearer <accessToken ou MASTER_KEY>
Content-Type: application/json

Resposta padrão

{
  "success": true,
  "data": {}
}

Erro

{
  "success": false,
  "error": "token ausente"
}

IDs de exercício usam o catálogo London (exerciseId), não só o sourceId da ExerciseDB. Login atual do app (só e-mail) deve passar a enviar também password. Collection Postman: docs/London-Fitness-API.postman_collection.json.

Ficha × treino feito

São duas coisas. A ficha é o modelo. O histórico é o que o aluno realmente executou.

1. Cadastrar / editar / excluir ficha — POST / PUT / DELETE /api/workouts. Soft delete em exclusão.
2. Começar (opcional) — POST /api/sessions copia a ficha ou um dia do plano. Se o app fechar, GET /api/sessions/current retoma.
3. Finalizar = salvar — POST /api/sessions/complete. Grava séries, volume, kcal e PRs. Sem sessão aberta, cria o registro já como completed.
4. Ver histórico — GET /api/history lista; GET /api/history/:id mostra série a série.

Plano com IA — Front ↔ Back ↔ Groq

O aluno termina o onboarding. O front não chama IA. O back chama a Groq, valida cada exerciseId no catálogo London (peito, costas, ombros, bíceps, tríceps, pernas, glúteos), grava o plano no Postgres e marca como ativo. O front só mostra GET /api/plans/active.

1. Front envia — POST /api/plans/generate com perfil (gender, goal, level, environment, daysPerWeek, equipment, focus). Auth Bearer.
2. Back monta o prompt — injeta o catálogo no formato id | displayName | musculo | equipamento | nivel. Modelo Groq, JSON mode, 45s.
3. Valida e grava — dropa id inventado ou da ExerciseDB. Dia com < 4 exercícios válidos é completado com os mais populares daquele músculo + equipamento (sem IA).
4. Front lê — a resposta já é o plano persistido (id do plano e de cada dia). Depois, GET /api/plans/active devolve o mesmo objeto.

Request do front

{
  "source": "ia",
  "name": "Plano hipertrofia",
  "gender": "homem",
  "goal": "hipertrofia",
  "level": "intermediario",
  "environment": "academia",
  "daysPerWeek": 4,
  "sessionDurationMin": 60,
  "equipment": ["halteres", "barra", "polia", "maquina"],
  "focus": ["corpo-inteiro"]
}

Resposta (plano salvo)

{
  "success": true,
  "data": {
    "id": "uuid",
    "name": "Plano hipertrofia · 4 dias",
    "source": "ia",
    "goal": "hipertrofia",
    "level": "intermediario",
    "daysPerWeek": 4,
    "days": [
      {
        "id": "uuid",
        "name": "A · Peito",
        "focus": ["peito"],
        "exercises": [
          { "exerciseId": "supino-reto-barra", "sets": 4, "reps": 8, "kg": 0, "restSec": 90 }
        ]
      }
    ]
  }
}

Enums: gender homem | mulher · goal hipertrofia | forca | emagrecimento | definicao · level iniciante | intermediario | avancado · environment academia | casa | peso-corporal · daysPerWeek 3–6.

equipment[]: halteres, barra, polia, maquina, banco, elastico, kettlebell, peso-corporal.

focus[]: peito, costas, ombros, biceps, triceps, pernas, gluteos, abdomen, corpo-inteiro. Vazio ou corpo-inteiro = corpo inteiro no catálogo disponível.

Regras: days.length = daysPerWeek · 5–8 exercícios/dia · kg sempre 0 · academia prioriza máquina, polia, halteres, barra. Sexo manda no split: mulher 4 dias = glúteos, pernas, superiores, glúteos+pernas · homem 4 dias = peito, costas, ombros+tríceps, bíceps. Id fora do catálogo é descartado.

Erro: timeout ou Groq fora → 502 { "success": false, "error": "ia_unavailable" }. O front usa fallback local.

O back não faz: devolver texto cru da IA · salvar exercício fora do catálogo · usar programId de template no lugar da IA · misturar ficha (/api/workouts) com plano ativo (/api/plans).
